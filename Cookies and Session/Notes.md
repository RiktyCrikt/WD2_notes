## Web/HTTP is stateless

Browser sent HTTP requests are independent of any other request 
    - Allows users to browse the web by following hypertext links
    - Can visit webpages in any order

HTTP also allows applications to to distribute/replicate content across multiple servers
    - Balances the load generated by a high number of requests

Where is this stateless nature useful?
    - When users need to browse or search collections of documents

What are the cons of this stateless nature?
    - Apps that require complex user interaction can't be implemented as a series of 
      unrelated, stateless web pages.
    - i.e. needing to save state of a customer's shopping cart while still searching the 
      the catalog. State of the cart will be stored somewhere.

## What are Cookies?

Used to store user or application state in a web browser.

Stored in a key/value pair.

Set by either:
    - Client-side JS
    - HTTP headers

# Setting a Cookie
Setting a Cookie:
 	- Syntax: int setcookie(string key, [string value], [int expire], [string path], [string domain], [int secure])
  	- Only the first argument is required (string key)
  
 	expire: Expiration date in seconnds since Epoch
  	path: Browser only includes this cookie when requesting resources that are in the specified path.
  		- If no path specified, cookie will be sent when requesting any resource from the
  		  specified domain.
  	domain: Browser will only include this cookie when requesting resources from this
  			domain. 
  		- No domain specified, browser only includes this cookie in requests set to the server 
  		  which set the cookie. 
 	secure: If set to one, cookie will onbly be sent by the browser when using secure (SSL) connection.
	
  	When a cookie is set, it is associated with:
  	- domain
  	- path
  	- an expiration

While the cookie is still fresh:
    - Browser will include its info (key/value pairs) along with any future requests made to the 
      associated domain/path.
